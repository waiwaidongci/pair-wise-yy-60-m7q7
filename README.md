# pair-wise-yy-60 碳减排项目监测证据核验与签发准备平台

按监测周期完成活动数据、排放因子、证据来源、异常波动和计算链核验。支持抽样任务、版本化数据修订、发现项闭环和签发前完整性检查。

## 技术栈

Next.js App Router、MUI、Zustand、TanStack Query、ky、Zod、TypeScript。

## 运行

```bash
npm install
npm run dev
```

访问 `http://localhost:62060`。`/api/evidence` 提供分页场景所需的本地 REST 数据接口。

## 断网出箱与可续作对账

现场核验可能断网，监测记录修订与发现项补录统一进入**本机出箱队列**（localStorage 持久化），把监测记录 → 发现项 → 签发准备接成可续作对账：

- **断网先留本机**：离线时修订/补录立即在本机可见并标记「本机暂存」，恢复网络（或手动「立即补交」）后按创建时间**按序补交**。
- **幂等补交**：每条操作带 `opId`，服务端对已确认 `opId` 回原结果，重复补交标记「重复已合并」，**不生成第二版**。
- **服务端新版本不被旧值盖回**：补交携带基线版本，服务端版本更新时返回 409 并附**双方版本与差异**；冲突项在三个页面均标记并**继续挡住签发检查**，核验员填写处理意见后选择「采用服务端版本」或「以新版为基线续交」，处理完才计入签发准备。
- **失败续交**：补交失败即停在该条，恢复后从最早未确认操作继续，已确认记录不再重交。
- **同批结果**：同一断网窗口的操作归入同一批次（batchId），总览 / 核验 / 签发三页显示同一批的确认、重复合并、待续交、冲突计数。

页内对账横条内置现场环境模拟：切换断网、模拟下一条补交失败、模拟服务端先行出新版本、重置演示数据，便于演练完整流程。
